# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A script that computes IBD-style **RS Rating** (Relative Strength percentile rank) for every stock listed on the Thai SET exchange, ranks them, writes Excel output, and produces a TradingView-format watchlist of top-ranked stocks. A Flask dashboard wraps the script for interactive use.

## Commands

This repo has its own git history with a private GitHub remote (`npskae24/RSRatingRanking`) — `.gitignore` excludes `venv/`, `driver/`, `backup/`, `log/`, generated `set_stock_list/` snapshots, and per-run output (`*.xlsx`, `watchlist_*.txt`).

No `requirements.txt`/`pyproject.toml` exists. **`python` on PATH may resolve to an unrelated venv missing deps (e.g. `selenium`) — use `py -3.12` (Windows py launcher) explicitly, not bare `python`, to hit the interpreter with everything installed.** The checked-in `venv/` is **broken** — it was created on a different machine (`C:\Users\Bank\...`) and its `pyvenv.cfg` points at a Python interpreter path that doesn't exist here. Don't try to activate it; use the system Python instead (this repo has been run successfully under Python 3.12, which already has pandas/numpy/yfinance/selenium/flask/requests/psutil installed — `html5lib` is the one package that had to be added manually, see below).

Run the ranking script directly (CLI, writes files to the repo root):
```
py -3.12 stock_ranking.py
```

Run the web dashboard (wraps `stock_ranking.py` as a subprocess via `sys.executable`, streams logs via SSE at http://localhost:5000):
```
py -3.12 app.py
```

There is no test suite and no lint config in this repo.

`stock_ranking_cli.py` is an unfinished argparse stub — not wired to anything, don't treat it as the entry point.

## Architecture

**`stock_ranking.py`** is the entire pipeline, run top-to-bottom under `if __name__ == '__main__':` (not organized into callable functions except a few I/O helpers). Reading the config constants block near the top (`PERIODS`, `WEIGHTS`, `RANKING_THRESHOLD`, `DAILY_OPERATION`, etc.) first is the fastest way to understand behavior — most tuning happens by editing these module-level constants, not the pipeline logic.

Pipeline flow:
1. **Stock universe** — scrape SET's listed-companies page (`download_SET_stock_names_html`) into `set_stock_list/`, parse the HTML table for symbols, then drop anything in `exclusion_list.txt`. `exclusion_list.txt` naturally accumulates dead entries for stocks that get delisted later — a non-matching entry is silently a no-op (`except ValueError: pass`), which is normal, not a bug to fix.
2. **Price history** — bulk-download close prices via `yfinance.download()` for all `{symbol}.BK` tickers. **`start=` must be a Python `datetime.date`, not `numpy.datetime64`** — `np.busday_offset(...)` returns `numpy.datetime64`, and newer `yfinance` raises `ValueError` for every ticker if you pass that directly (see Known issues below); the call site does `.astype(datetime.date)` right before the `yfinance.download()` call for this reason — don't remove it, and don't apply `.astype()` further upstream since `return_start_date`/`start_download_date` are also compared against a `DatetimeIndex` elsewhere and need to stay `numpy.datetime64`/`pd.Timestamp`-comparable there. If today's date isn't present in the yfinance result (common when the market hasn't closed yet), it falls back to scraping `siamchart.com` with Selenium (`download_siamchart_prices`) — this path is currently unusable in this dev environment (see Known issues) and is normally avoided by setting `SKIP_TODAY_PRICE_DOWNLOAD = True`.
3. **Fundamentals (now disabled by default)** — `yahoo_finance_scraper.get_stock_statistics()` fetches per-symbol via `yfinance.Ticker(...).info` (multiprocessed, `N_THREADS` workers, jittered + retried to avoid bursting Yahoo's unofficial endpoint), for ROE, margins, market cap, 52w high, quarterly revenue/earnings growth. **`SKIP_STOCK_STATISTICS = True` as of 2026-08-20** — Thai `.BK` fundamentals via yfinance `.info` are too incomplete/unreliable to depend on, so the system moved to 100%-technical (see step 4a below); the RS Rating itself never depended on this step, only the extra fundamentals output columns (`ROE`, `marketCap`, etc.) did, and those are now empty unless you flip the flag back. `REQUIRED_STATS_FUNDAMENTALS` in `stock_ranking.py` maps yfinance's flat `.info` field names to friendly output column names — selection uses `.reindex()` (not a plain column select) so a field yfinance doesn't return for one stock becomes `NaN` instead of an exception that silently drops the friendly renaming for every stock. `df_stats_fundamentals`'s index isn't guaranteed to be a subset of `df_prices.columns` (a stock can have fundamentals but get dropped from price data for insufficient history) — the `52wHighToClosePrice` loop must iterate `.index.intersection(df_prices.columns)`, not the raw index, or it raises `KeyError`.
4. **RS calculation** — returns computed over four lookback windows (`PERIODS = [63,126,189,252]` trading days ≈ 3/6/9/12 months), each percentile-ranked, then combined into one RS score via `WEIGHTS = [0.4,0.2,0.2,0.2]` (heaviest weight on the shortest/most recent period) and percentile-ranked again into the final RS Rating.

   **Output column names are swapped vs. IBD convention** (`stock_ranking.py:434-439,550-551`) — `df_rs` (the weighted-sum, unbounded raw score) is written to the **`RS Rating (Type longest)`** column; `df_rs_rank = df_rs.rank(pct=True)` (the actual 0-1 percentile, what `RANKING_THRESHOLD` filters on) is written to the **`RS Score`** column. So "RS Score" is the percentile and "RS Rating" is the raw score — backwards from what the names suggest. Sorting by either gives the same order (percentile is a monotonic transform of the raw score), but only `RS Score` is meaningful as "top X%".
4a. **Technical stats (price/volume only, always on)** — added 2026-08-20 as the fundamentals replacement. `df_volume` is pulled alongside `df_prices` from the same `yfinance.download()` call (and cached to `backup/volume.csv` the same way `close_price.csv` is), then: `TightBase`/`BreakoutVolumeConfirmed`/`VolumeRatio` from rolling high-low range and volume-vs-`VOLUME_AVG_WINDOW`-day-average (`BASE_LOOKBACK`, `BASE_TIGHTNESS_MAX`, `BREAKOUT_LOOKBACK`, `BREAKOUT_VOLUME_MULT` config knobs); `HighToClose_252d` as a pure-price replacement for the old fundamentals-derived `52wHighToClosePrice`; `MarketRegimeUp` from an equal-weight synthetic SET index built from `df_prices` itself (`sr_market_index = (1+mean daily return).cumprod()` vs its `MARKET_TREND_WINDOW`-day MA) — deliberately not an external `^SET`-style ticker, since the universe is already downloaded and the correct Yahoo symbol for the Thai SET index isn't confirmed; and `Sector`/`SectorRS` by reusing the `Sector` column already present in the scraped SET listed-company table (`get_SET_stock_sectors()`) and averaging `df_rs_rank` per sector — no separate sector-index download. All joined into `df_stats_technical` and merged into the daily output the same way `df_stats_fundamentals` used to be.
5. **Output** — writes two Excel copies per run (`backup/{date}_{timestamp}.xlsx` for history, `{date}.xlsx` at repo root as "latest"), plus `watchlist_{timestamp}.txt` (TradingView `SET:XXX` format) for stocks at/above `RANKING_THRESHOLD` (default 0.8 = top 20%). Also dumps `backup/close_price.csv`, `backup/volume.csv`, and `backup/return.csv` so a future run can skip re-downloading (`SKIP_PRICE_DOWNLOAD`).

Note: several spots (`df_returns.T.groupby(level=1)...`, the RS weighted-sum block) use transpose/stack workarounds specifically because pandas 2.x removed `groupby(axis=1)` — don't "simplify" these back to the old `axis=1` form.

**`app.py`** is a thin Flask wrapper: `/api/run` spawns `stock_ranking.py` as a subprocess and streams its stdout to the browser over SSE (`/api/stream`); `/api/results` reads the latest `{date}.xlsx` and returns the top 200 rows as JSON; `/api/watchlist` and `/api/files` expose the other generated artifacts. It never imports pipeline logic directly — it only shells out to the script and reads the files it produces.

**`yahoo_finance_scraper.py`** is a standalone utility module (no dependency on `stock_ranking.py`) for pulling arbitrary Yahoo Finance `quoteSummary` modules for a list of symbols in parallel via `multiprocessing`. See Known issues — the endpoint it hits no longer exists.

## Config knobs (top of `stock_ranking.py`)

- `DAILY_OPERATION` — `True` computes only today's rating (normal use); `False` recomputes RS ratings for the full history back to `GLOBAL_START_DATE` (slow, used for backfills/one-off repopulation).
- `SKIP_*` flags — skip network calls (name download, price download, stats download) and reuse local cache from `backup/`, useful for iterating on ranking logic without re-hitting Yahoo/SET. `SKIP_TODAY_PRICE_DOWNLOAD` is still `True` (chromedriver mismatch below is unfixed). `SKIP_STOCK_STATISTICS` is now `True` (100%-technical pivot as of 2026-08-20, see Architecture above) — flipping it back to `False` re-fetches fundamentals via `yfinance.Ticker.info` and re-adds real per-run network time (~800 stocks / `N_THREADS` workers, throttled).
- `DAILY_FILLING_MODE` / `FORWARD_FILL` — how missing returns are handled for recently-listed stocks with insufficient price history.

## Known issues / fragile external integrations

These were hit and diagnosed by running the pipeline end-to-end; each is either fixed in code or worked around with a config flag — read this before "fixing" something that's already accounted for.

- **SET's stock-list endpoint requires a browser-like `User-Agent`.** `download_SET_stock_names_html()` now sends `headers=HEADERS` (imported from `yahoo_finance_scraper`) — without it, SET's Incapsula WAF returns HTTP 200 with an empty bot-challenge page instead of the real HTML table, and `pd.read_html()` fails confusingly (`No tables found` or a `html5lib` import error, depending on flavor fallback). Incapsula can also rate-limit an IP for a while after repeated requests in a short window (seen firsthand while debugging) — a sudden reappearance of the empty-page symptom after this was already fixed is more likely transient rate-limiting than a regression.
- **`pd.read_html()` needs `html5lib` installed**, not just `lxml`. SET's HTML is malformed enough that the strict `lxml` parser raises `No tables found` on it; pandas' default flavor order falls through to `bs4`, which hard-requires `html5lib`. Install with `pip install html5lib` if missing.
- **Yahoo's `quoteSummary` v11 API (`query2.finance.yahoo.com/v11/finance/quoteSummary/...`) has been discontinued** — every request now returns HTTP 404. `yahoo_finance_scraper.py` no longer uses it — it fetches via `yfinance.Ticker(...).info` instead, which handles Yahoo's `v10` crumb+cookie auth internally and has been verified working for `.BK` tickers (confirmed live: `marketCap`, `returnOnEquity`, `profitMargins`, `fiftyTwoWeekHigh`, `revenueGrowth`, `earningsQuarterlyGrowth`, `totalRevenue`, `netIncomeToCommon` all present). It's an unofficial API surface, so Yahoo may still rate-limit a datacenter IP (e.g. a VPS) harder than this dev machine — if `get_single_stock_statistics` starts raising `ConnectionError` for most/all stocks, that's the first thing to suspect, not a logic bug. **This was hit on this dev machine too** — `N_THREADS = 25` against the ~800-stock universe triggered HTTP 429 ("Too Many Requests") for the majority of stocks in a single run; lowered to `N_THREADS = 8`, which cleared it (confirmed 0 rate-limit hits in the following run). If it recurs even at 8, drop it further before touching `MAX_RETRIES`/`TIMEOUT` in `yahoo_finance_scraper.py` — Yahoo's block window runs minutes, longer than the 2/5/10s backoff, so more retries inside an active block just burns more requests without helping (and `TIMEOUT`'s length must stay equal to `MAX_RETRIES`, or `TIMEOUT[i]` raises `IndexError`).
- **Fundamentals cache (`backup/stats_fundamentals.csv`)** backfills any field still `NaN` after a run (rate-limited or genuinely missing from Yahoo) from the previous successful run's values, via `combine_first` restricted to the current stock universe — added because fundamentals change quarterly, so a stale value beats a blank one. Only written when `SKIP_STOCK_STATISTICS = False` and the fetch produced data, so a skipped/empty run never clobbers the cache. First run after adding this (or after deleting the cache file) has nothing to backfill from, which is expected, not a bug.
- **`driver/chromedriver_v131.exe` doesn't match the Chrome actually installed in this dev environment** (Chrome 151 at last check), and no matching version exists under `driver/`. The Selenium/siamchart fallback path (triggered when yfinance lacks today's price) will fail with `FileNotFoundError` if exercised. Worked around via `SKIP_TODAY_PRICE_DOWNLOAD = True`; a real fix means downloading a matching chromedriver.
- **`th_holidays.csv`** (`set_stock_list/th_holidays.csv`) is a manually-maintained list that goes stale — the script only warns when it's behind today's date, it doesn't fail. Long stretches of stale holidays can silently skew the daily download-window calculation around holiday dates.

## Data directories

- `backup/` — timestamped Excel snapshots + `close_price.csv`/`return.csv`/`stats_fundamentals.csv` cache, growing unbounded (no cleanup logic exists). `close_price.csv`/`volume.csv`/`return.csv` hold only a rolling ~252-trading-day window, not full history — full multi-year history only exists in the OneDrive mirror's timestamped `backup/*.xlsx` snapshots (no volume there, sparse dates).
- `log/` — one timestamped log file per run.
- `set_stock_list/` — timestamped snapshots of the scraped SET company list HTML + `th_holidays.csv` (manually maintained; the script warns if it's stale).
- `backtest/` — ad-hoc backtest scripts (git-tracked) validating pipeline signals against historical data; their `*.csv`/`*.png` output is gitignored, not the scripts themselves. Established pattern as of 2026-08-21, worth following rather than rediscovering:
  - `price_cache_2018_2026.csv` / `volume_cache_2018_2026.csv` / `low_cache_2018_2026.csv` — a continuous daily OHLCV panel for the full current universe (~867 `.BK` tickers), pulled once via `yfinance.download()` and cached here. This is the dataset for any 2020+ backtest — check for it before re-downloading (a fresh pull takes several minutes for the full universe). It's a superset of `backup/`'s rolling ~1yr cache and far denser than the OneDrive sparse snapshots.
  - `simulate_equity_curve_2020_2026.py` is the baseline day-by-day portfolio simulator (entries/exits/sizing, not just a statistical decile study); each `simulate_<variant>_2020_2026.py` (`_mdd_sizing`, `_2r3r5r_exit`, `_txn_cost`, `_full_scoring`, `_full_process[_fixed]`, `_ultimate`) copies it and isolates changing exactly one thing (exit rule, sizing/throttle, transaction costs, scoring formula) for a clean before/after comparison — don't edit a variant to also change the baseline's shared logic, copy again instead.
  - `findings_*.md` — one short write-up per isolated experiment (numbers + a few sentences of interpretation). All findings get consolidated into a dated section of `../TRADING PROCESS/TRADING PROCESS V4.2 DRAFT (technical-only addendum).md` (outside this repo) — that addendum, not this folder, is the durable record of what was tested and what it means for the live process; skim it before re-running an experiment that might already be answered there (including a real "sizing throttle can fully freeze the portfolio in cash for years" bug already found and fixed — see its MDD-throttle correction section before trusting a naive halt-based sizing rule).
  - The real scoring weights (`SCORING SYSTEM V1.x.xlsx`, `OneDrive\STOCKTRADING\HTTP4\`) are nested-IF Excel formulas referencing a `PARAMETER` sheet — read them with `openpyxl(data_only=False)` and trace the actual formula, not just the `SCORING TABLE` sheet's displayed bucket text, which has been caught stale/wrong relative to the live formula more than once.
  - **Default `POSITION_SIZE_PCT` for new backtest scripts is 10%, not the earlier 5%** — decided 2026-08-21 as the live-trading fresh-account (DD=0) sizing (see the addendum's "Live decision" section) and now the default in `simulate_ultimate_2020_2026.py` (the shared source most variants import constants from). 5% was the original "baseline" figure quoted throughout older findings docs and is still valid as a historical data point — those old numbers are correctly labeled by their tested sizing, not silently invalidated — but any new script/variant should start from 10% unless the task specifically calls for a sizing comparison (see `findings_survivorship_try3.md` for the 5%/10%/12.5% sweep this decision came from). **Also as of 2026-08-21, `ROUNDTRIP_COST_PCT_PER_SIDE` is 0.0809%/side** (0.07% confirmed commission + fees + VAT, corrected from an earlier 0.15%-commission guess — see `findings_txn_cost.md`'s correction note) — same shared-source situation, same "old numbers still valid at their old rate" caveat.
  - **Stacked-execution simulations (anything importing from `simulate_ultimate_2020_2026.py`) are chaos-sensitive, not just biased** — the MDD throttle / loss-streak halt / NAV+2% escalation are discrete thresholds evaluated fresh each day against the exact equity value, so a few basis points of difference anywhere upstream (fee rate, sizing, an extra spliced-in ticker) can flip which side of a threshold a day lands on and cascade into a materially different multi-year trade sequence — confirmed directly: lowering the transaction cost once made the final result WORSE, and a 12.5%-sizing run underperformed both 5% and 10% (non-monotonic). Treat any single run's CAGR/DD as a wide band (~20-33% CAGR seen so far), not a point estimate — see `findings_survivorship_try3.md` for the full writeup.
  - **None of the `simulate_*.py` scripts model liquidity/slippage** — `AvgValue_20d` exists in the pipeline output but is never referenced in any backtest sim; fills happen at the exact close price regardless of position size vs. that stock's daily traded value. Fine at the ~100K THB `STARTING_CAPITAL` these scripts default to, but sizing/capacity conclusions don't hold as-is at larger portfolio sizes — check `alloc_thb` (trade log) against `AvgValue_20d` (latest ranking xlsx) per symbol before trusting a return number at bigger capital.

## Reusing technical-signal formulas outside the pipeline (e.g. backtesting)

`TightBase`/`BreakoutVolumeConfirmed`/`MarketRegimeUp` (stock_ranking.py:449-462) are computed per-date-per-symbol except `MarketRegimeUp`, which is a single per-date Series. `some_df & market_regime_series` silently aligns on **columns**, not rows — it does not broadcast the per-date flag down each date's row. Broadcast explicitly first, e.g. `pd.DataFrame(np.repeat(sr.values[:,None], df.shape[1], axis=1), index=df.index, columns=df.columns)`, before ANDing with a symbols-wide DataFrame.
